# Module 01 — Interview Questions

> The most common **Introduction to Java** interview questions, with concise model answers. Practice by covering the answer, speaking it aloud, then checking.

---

## Q1. What is Java?

**Answer:** Java is a high-level, object-oriented, platform-independent programming language developed by Sun Microsystems (now Oracle). It compiles to bytecode that runs on any device with a Java Virtual Machine (JVM), following the "Write Once, Run Anywhere" philosophy.

---

## Q2. Who created Java and when?

**Answer:** James Gosling, along with Mike Sheridan and Patrick Naughton, created Java at Sun Microsystems starting in 1991. It was originally called Oak and was released publicly as Java 1.0 on January 23, 1996.

---

## Q3. Why is Java called "platform independent"?

**Answer:** Java source compiles to bytecode (`.class` files) rather than OS-specific machine code. Any platform with a JVM can execute the same bytecode, so the program runs identically on Windows, macOS, and Linux without recompilation.

---

## Q4. List the main features of Java.

**Answer:** Simple, object-oriented, platform independent, secure, robust, multithreaded, architecture neutral, portable, high performance (via JIT), dynamic, distributed, and both interpreted and compiled.

---

## Q5. What is the difference between JDK, JRE, and JVM?

**Answer:**
- **JDK** (Java Development Kit) = tools to develop and run Java (compiler `javac`, `jar`, `javadoc`) + JRE. For developers.
- **JRE** (Java Runtime Environment) = JVM + core libraries. For running programs.
- **JVM** (Java Virtual Machine) = the engine that loads, verifies, and executes bytecode.

Relationship: **JDK ⊃ JRE ⊃ JVM**.

---

## Q6. Is Java a compiled language or an interpreted language?

**Answer:** Both. `javac` compiles source into bytecode (compiled step), and the JVM interprets that bytecode while its JIT compiler converts hot bytecode into native machine code at runtime (interpreted/compiled step).

---

## Q7. What is the JIT compiler?

**Answer:** The Just-In-Time compiler is part of the JVM's execution engine. It monitors bytecode execution, identifies frequently executed ("hot") methods, and compiles them to native machine code once, after which they run at near-native speed.

---

## Q8. What are the main components of JVM architecture?

**Answer:** ClassLoader (loads classes), Runtime Data Areas (method area, heap, stack, PC register, native method stack), and the Execution Engine (interpreter, JIT compiler, garbage collector).

---

## Q9. What is the Java heap and the Java stack?

**Answer:** The **heap** is shared memory where all objects and arrays live; it is garbage-collected. The **stack** is per-thread memory storing local variables, method frames, and references to heap objects.

---

## Q10. What does "Write Once, Run Anywhere" (WORA) mean?

**Answer:** A single Java source file compiles to platform-neutral bytecode that can run on any operating system that has a JVM. The JVM translates bytecode into the host system's instructions.

---

## Q11. Why is the `main` method declared `public static void`?

**Answer:**
- `public` — accessible to the JVM from outside the class.
- `static` — callable without creating an object of the class.
- `void` — returns no value to the operating system.

---

## Q12. What is the signature of the main method?

**Answer:** `public static void main(String[] args)` where `args` holds command-line arguments.

---

## Q13. Which Java version is LTS and why should enterprises use it?

**Answer:** Java 8, 11, 17, 21, and 25 are LTS. Enterprises use LTS because it receives security patches and bug fixes for many years, ensuring stability and long-term support.

---

## Q14. What is bytecode?

**Answer:** Bytecode is the platform-neutral intermediate representation of Java source, generated by `javac`. Stored in `.class` files, it is executed by the JVM and has a major version tied to the Java release (52 = Java 8, 61 = Java 17, 65 = Java 21).

---

## Q15. What is the ClassLoader and the Parent Delegation Model?

**Answer:** A ClassLoader loads `.class` files into memory. The Parent Delegation Model means a class loader first delegates class-loading requests to its parent; only if the parent cannot find the class does it try itself. This prevents duplicate definitions and secures core classes.

---

## Q16. Where is Java used in the real world?

**Answer:** Android development, enterprise backend systems (Spring Boot), banking and finance, e-commerce, big data (Hadoop, Spark, Kafka), IoT/embedded, web services, and cloud infrastructure. Major users include Netflix, Amazon, Uber, LinkedIn, and Twitter/X.

---

## Q17. What is the difference between Java and JavaScript?

**Answer:** They are completely different languages. Java is compiled to bytecode and runs on a JVM (server/backend/enterprise); JavaScript is an interpreted scripting language that runs in browsers (frontend) and Node.js. Only the name is similar.

---

## Q18. What are compile-time and runtime errors?

**Answer:** Compile-time errors are detected by `javac` (syntax/semantic errors) and prevent compilation. Runtime errors occur during execution and surface as exceptions (e.g., `ArithmeticException`, `ArrayIndexOutOfBoundsException`).

---

## Q19. Explain the Java execution flow.

**Answer:** Source code → `javac` compiles to bytecode → ClassLoader loads classes → Bytecode Verifier checks security → Execution Engine interprets bytecode and JIT-compiles hot paths → machine code runs on the hardware.

---

## Q20. What does `javap` do?

**Answer:** `javap` is the Java disassembler tool that prints the bytecode (with `-c`) or method signatures (with `-p`) of a compiled `.class` file.

---

## 🧠 Tips for the Interview

1. Answer **structure first**: give the definition, then the "why," then an example.
2. Pair every theoretical answer with a **one-line code/diagram reference**.
3. If asked about versions, mention the **LTS line** (8, 11, 17, 21, 25) and the 6-month cadence.
4. Speak about JVM internals confidently — it signals deep understanding.
5. Use the **restaurant / postal** analogies to make complex ideas memorable.
